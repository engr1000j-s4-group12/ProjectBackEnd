# 后端岗位交付说明

## 1. 岗位目标

后端岗位的目标不是只完成几个 API，而是交付一个设备可以稳定调用、可以部署、可以测试、可以维护的云后端服务。

最小交付目标：

```text
给出一个 HTTPS 云后端地址，ESP32 上传照片后能拿到当前位置，
再提交目的地后能拿到可播报的导航步骤。
```

建议系统形态：

```text
ESP32 小智终端
  -> 校园网或热点
  -> 云服务器 HTTPS
  -> FastAPI 后端
  -> VLM 服务
  -> 返回定位、路线和展品上下文
```

## 2. 核心交付物

### 2.1 云端可访问的后端服务

后端岗位需要交付一个公网可访问的服务地址，例如：

```text
https://guide.example.com/health
https://guide.example.com/docs
```

基本要求：

- FastAPI 服务部署在云服务器；
- 支持 HTTPS；
- 服务重启后能自动恢复，例如使用 systemd、Docker Compose、Nginx 或 Caddy；
- 已配置 VLM 相关环境变量；
- `/health` 可用于检查服务是否在线；
- 服务日志可查看，方便演示现场排查问题。

需要配置的环境变量：

```bash
VLM_BASE_URL="https://你的VLM服务地址/v1"
VLM_API_KEY="你的API密钥"
VLM_MODEL="支持图片输入的模型名称"
VLM_TIMEOUT_SECONDS="45"
```

真实 API Key 只能放在服务器环境变量或不提交的配置文件中，不得写入代码、JSON 数据或 Git。

### 2.2 设备可稳定调用的 API

后端岗位至少需要维护以下接口：

```text
GET  /health
GET  /api/v1/places
POST /api/v1/localize
POST /api/v1/localize/visual
POST /api/v1/localize/image
POST /api/v1/route
GET  /api/v1/exhibits
GET  /api/v1/exhibits/{exhibit_id}
POST /api/v1/exhibits/{exhibit_id}/context
GET  /api/v1/resolve
```

设备端最关键的是：

```text
POST /api/v1/localize/image
POST /api/v1/route
```

图片定位接口要求：

```http
POST /api/v1/localize/image
Content-Type: multipart/form-data
```

表单字段：

```text
image: JPEG、PNG 或 WebP 图片，最大 5 MiB
floor_hint: 可选楼层数字
```

路线规划接口要求：

```http
POST /api/v1/route
Content-Type: application/json
```

请求示例：

```json
{
  "from_location": "LB-1F-ENTRANCE",
  "to_location": "EXHIBIT-ROBOT",
  "language": "zh",
  "accessible_only": false
}
```

响应中必须包含：

- 起点 ID；
- 终点 ID；
- 总距离；
- 分段导航步骤；
- 中英文可播报指令。

### 2.3 错误状态和设备处理约定

视觉定位返回状态：

```text
matched: 找到明显优于其他地点的候选位置
ambiguous: 多个位置得分接近，需要用户确认或重新拍照
not_found: 视觉证据不足，不能开始导航
```

设备端处理建议：

| 状态 | 后端含义 | 设备端处理 |
| --- | --- | --- |
| `matched` | 定位成功 | 若 `needs_confirmation=false`，可继续规划路线 |
| `ambiguous` | 位置不明确 | 播报候选位置，让用户确认或重新拍照 |
| `not_found` | 无法定位 | 提示用户重新拍照或使用二维码兜底 |

常见 HTTP 错误码：

| 错误码 | 含义 | 设备端处理 |
| --- | --- | --- |
| `400` | 请求内容为空或格式错误 | 提示重新操作 |
| `404` | 地点或展品不存在 | 提示目的地未知 |
| `413` | 图片超过大小限制 | 降低图片大小后重试 |
| `415` | 图片格式不支持 | 改用 JPEG、PNG 或 WebP |
| `422` | 不存在满足条件的路线 | 提示无法到达或切换路线条件 |
| `502` | VLM 响应异常 | 提示视觉识别服务暂不可用 |
| `503` | VLM 未配置或不可用 | 提示后端服务未就绪 |

### 2.4 接口文档

后端岗位需要交付一份给固件岗位使用的接口说明，至少包括：

- 云服务器地址；
- 每个设备接口的请求方法；
- 请求字段说明；
- 响应 JSON 示例；
- 错误码说明；
- ESP32 multipart 上传图片字段名；
- 超时建议；
- 失败时设备应如何播报；
- 是否需要 token 鉴权。

FastAPI 自动文档也必须可访问：

```text
https://guide.example.com/docs
https://guide.example.com/openapi.json
```

### 2.5 部署文档和启动脚本

后端岗位需要让其他成员可以复现部署，不能只停留在个人电脑可运行。

建议交付：

- 服务器部署步骤；
- Python 环境或 Docker 环境说明；
- 依赖安装命令；
- 环境变量说明；
- 启动命令；
- 重启服务方式；
- 查看日志方式；
- 更新代码流程；
- 回滚方式。

后端本地启动命令：

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r server/requirements-dev.txt
uvicorn server.app.main:app --host 0.0.0.0 --port 8000
```

生产部署时建议在反向代理后运行：

```text
公网 HTTPS
  -> Nginx 或 Caddy
  -> 127.0.0.1:8000
  -> FastAPI
```

### 2.6 测试和验收用例

后端岗位需要保证项目自己的后端测试通过：

```bash
.venv/bin/pytest tests
```

注意：不要直接从仓库根目录无参数运行 `pytest`，否则可能误收集 `xiaozhi-esp32/managed_components` 里的第三方测试。

至少需要覆盖以下场景：

- 健康检查；
- 地点 ID 与别名解析；
- 普通路线规划；
- 无障碍路线规划；
- 起点等于终点；
- 未知地点返回错误；
- 视觉定位成功；
- 视觉定位模糊；
- 视觉定位失败；
- 图片格式错误；
- VLM 未配置；
- 展品上下文生成。

### 2.7 数据维护能力

本项目定位质量高度依赖 `data/building_map.json` 和 `data/exhibits.json`。

后端岗位需要负责维护这些数据结构：

- 地图节点；
- 地点别名；
- 视觉地标；
- 地标权重；
- 地图连线；
- 普通路线和无障碍路线；
- 中英文导航指令；
- 展品资料；
- 展品和地点的关联。

地图数据变更后必须验证：

- 节点 ID 不重复；
- 边引用的节点存在；
- 距离大于 0；
- 展品引用的地点存在；
- 视觉地标 aliases 非空；
- 修改后后端能正常启动；
- 相关路线和视觉定位测试通过。

## 3. 云端部署重点

### 3.1 为什么适合云部署

当前后端是 FastAPI 服务，核心数据是 JSON 文件，没有复杂数据库依赖，因此适合部署到云服务器。

云部署相比电脑局域网后端的优点：

- ESP32 只需要能访问公网；
- 不依赖演示电脑和设备在同一局域网；
- 更适合团队协作和远程调试；
- 可以提前固定服务地址；
- 可以通过日志看到设备请求是否到达后端。

### 3.2 主要难点

后端部署本身难度较低，主要难点在：

- ESP32 是否能稳定连接校园网；
- 校园网是否需要网页认证；
- 校园网是否限制 IoT 设备出网；
- HTTPS 证书是否配置正确；
- 图片上传是否和后端字段名一致；
- VLM 服务响应是否稳定；
- 设备端超时、重试和播报逻辑是否完整。

演示时建议准备手机热点或自有路由器作为兜底网络。

### 3.3 公网安全要求

后端部署到公网后，必须增加基础防护。

建议至少实现：

- 设备 token 鉴权，例如 `X-Device-Token`；
- 上传图片大小限制；
- 图片类型限制；
- 请求日志；
- VLM 调用超时；
- 不在日志中输出 API Key；
- 不把真实密钥提交到 Git。

当前后端已经限制图片最大 5 MiB，并限制图片格式为 JPEG、PNG 和 WebP。公网部署前仍建议增加设备鉴权，避免接口被外部随意调用并消耗 VLM 额度。

## 4. 与固件岗位的接口边界

后端岗位负责：

- FastAPI 服务；
- 云部署；
- VLM 调用；
- 视觉特征解析；
- 视觉地标匹配；
- 路线规划；
- 展品上下文；
- API 文档；
- 测试；
- 日志和错误处理；
- 地图和展品数据结构维护。

后端岗位不应完全负责：

- ESP32 摄像头驱动；
- ESP32 MCP 工具注册；
- 小智语音交互逻辑；
- 设备端 Wi-Fi 配网；
- TTS 播报；
- 现场真实数据采集；
- 展品内容真实性审核。

但后端岗位必须和固件岗位共同确认：

- 云后端基础地址；
- 图片上传字段名；
- 请求超时时间；
- 鉴权方式；
- 路线返回格式；
- `matched`、`ambiguous`、`not_found` 的设备端处理逻辑。

## 5. 建议后续固件对接接口

建议固件岗位增加两个设备端 MCP 工具：

```text
museum.visual_localize
museum.plan_route
```

推荐流程：

```text
用户提出导航请求
  -> 小智 LLM 调用 museum.visual_localize
  -> ESP32 拍摄当前环境
  -> ESP32 上传照片到 /api/v1/localize/image
  -> 后端返回 matched、ambiguous 或 not_found
  -> 如果定位需要确认，设备询问用户或重新拍照
  -> 用户确认目的地
  -> ESP32 调用 /api/v1/route
  -> 设备只播报 announcement；steps 仅供后台重新定位和调试
```

如果小智已有 VLM 能稳定输出结构化特征，也可以使用：

```text
POST /api/v1/localize/visual
POST /api/v1/route
```

这样能减少一次图片上传和 VLM 调用，但前提是结构化输出格式稳定。

## 6. 验收标准

后端岗位满足以下条件即可认为完成阶段性交付：

- 云端 `/health` 可访问；
- 云端 `/docs` 可访问；
- FastAPI 服务支持 HTTPS；
- 服务器重启后服务能自动恢复；
- VLM 环境变量已正确配置；
- ESP32、手机或电脑能通过公网调用接口；
- `/api/v1/localize/image` 能返回 `matched`、`ambiguous` 或 `not_found`；
- `/api/v1/route` 能返回中英文分段导航步骤；
- `.venv/bin/pytest tests` 通过；
- 有接口文档；
- 有部署文档；
- 有错误码说明；
- 有基础鉴权方案；
- 有日志查看方式；
- 演示前能确认设备请求是否到达服务器。
