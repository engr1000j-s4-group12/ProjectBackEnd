# 小智终端云端部署与联调

## 1. 最终部署结构

```text
管理者浏览器 ─HTTPS─> ProjectBackEnd /admin ─┐
                                              ├─> SQLite + uploads 持久卷
小智设备 ─HTTPS─> /api/device/v1/* ──────────┤
                                              ├─> VLM
电脑 Agent ─HTTPS─> /mcp ────────────────────┘
```

小智原有 WebSocket/MQTT 语音链路继续连接小智云端。设备上的 `museum.*` MCP 工具作为 HTTP 客户端访问 ProjectBackEnd；ProjectBackEnd 不接管 Opus、STT 或 TTS。

## 2. 云端启动

```bash
git clone <repository-url> ProjectBackEnd
cd ProjectBackEnd
git switch CYH
cp .env.example .env
```

至少修改：

```dotenv
ADMIN_USERNAME=admin
ADMIN_PASSWORD=<随机长密码>
DEVICE_API_TOKEN=<随机设备Token>
MCP_API_TOKEN=<随机MCP Token>
VLM_API_KEY=<VLM密钥>
VLM_BASE_URL=<兼容接口地址>
VLM_MODEL=<模型名>
GUIDE_DOMAIN=<解析到云服务器的域名>
```

HTTP 启动：

```bash
docker compose up -d --build
```

域名 HTTPS 启动：

```bash
docker compose -f docker-compose.yml -f docker-compose.https.yml up -d --build
```

验证：

```bash
curl https://$GUIDE_DOMAIN/health
curl https://$GUIDE_DOMAIN/api/device/v1/capabilities \
  -H 'Device-Id: TEST-DEVICE' \
  -H "Authorization: Bearer $DEVICE_API_TOKEN"
```

## 3. 固件配置

将 `Project-2/origin/backend-api` 中 `MuseumClient::BaseUrl()` 的硬编码局域网地址替换为 NVS、编译配置或 OTA 下发的：

```text
https://<GUIDE_DOMAIN>
```

每个 HTTP 请求增加：

```http
Authorization: Bearer <DEVICE_API_TOKEN>
Device-Id: <设备MAC>
Client-Id: <设备UUID>
Firmware-Version: <固件版本>
```

摄像头上传格式与小智 `Esp32Camera::LocalizeImage` 一致：

```http
POST /api/device/v1/localize/image
Content-Type: multipart/form-data

image=<camera.jpg>
floor_hint=3
```

## 4. 设备 MCP 工具映射

| 工具 | 后端接口 | 返回用途 |
|---|---|---|
| `museum.get_guide_context` | `GET /api/device/v1/guide/context` | Persona、来访任务、当前位置资料 |
| `museum.resolve_place` | `POST /api/device/v1/resolve-place` | 目的地名称解析 |
| `museum.localize_image` | `POST /api/device/v1/localize/image` | 拍照定位 |
| `museum.localize_visual` | `POST /api/device/v1/localize/visual` | 使用已有 VLM 特征定位 |
| `museum.plan_route` | `POST /api/device/v1/route` | 获得最终播报 |
| `museum.search_knowledge` | `GET /api/device/v1/knowledge/search` | 查询学院、建筑、展览资料 |

不要把完整地点列表发送给小智 LLM；目的地应通过 `resolve-place` 搜索。不要逐条播报 `steps`，只播报 `announcement`。

## 5. 标准调用流程

```text
用户询问路线
→ museum.get_guide_context
→ 如果没有当前节点，museum.localize_image
→ matched 后 museum.resolve_place
→ museum.plan_route
→ 将 announcement 交给 TTS
→ 移动后定期再次 museum.localize_image
→ 使用新节点重新规划剩余路线
```

定位结果处理：

- `matched`：使用 `current_node`；
- `ambiguous`：播报 `speak`，调整设备朝向后重拍；
- `not_found`：靠近门牌或展板后重拍；
- HTTP 502/503：播报响应中的错误提示并联系工作人员。

## 7. 数据与备份

容器内持久数据位于 `/app/runtime`，Docker 卷名为 `guide_runtime`：

- `guide.sqlite3`：全部数据库数据和设备会话；
- `uploads/`：管理端上传附件。

重建镜像不会删除该卷。删除卷会删除运行数据，因此禁止使用 `docker compose down -v`，除非明确执行数据重置。
